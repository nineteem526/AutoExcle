# 验证记录与已知限制

> 本页为早期源码验证记录，不代表 V13 已运行相同测试或具备相同布局。V13 的本地验证范围、未覆盖交互及限制见[完整项目流程](PROJECT_REPORT.md#10-验证事实与验收边界)；本次文档更新不包含工作簿复测。

## 已执行验证

开发阶段通过 Windows 桌面版 Excel 16.0 COM 自动化，在独立工作簿副本中运行宏核心过程。以下为当时的验证记录，不代表本仓库已有自动化 CI 或可直接运行的完整测试套件。

| 场景 | 结果 |
|---|---|
| 覆盖 Planned 的单单元格引用公式 | 成功写入固定批次，Automatic 公式保持不变 |
| 区域项目集中到一个批次 | 展示容量从 8 行扩充到 28 行，按明细顺序逐项比对通过 |
| 重复刷新 | 没有重复插入不必要的行 |
| 明细第 1001 行 | 新增记录显示在总览中 |
| 同一区域、同一批次的两个同名项目 | 分别定位到对应明细，修改第二条未影响第一条 |
| 输入未配置批次 | 明确拒绝，未修改原批次 |
| 增加第 25 批表头 | 刷新后新列生成公式并显示记录 |
| 未配置区域 | 明确报错，恢复事件与屏幕更新状态 |
| 交付副本数据比对 | 明细与运输规则表的原始值及公式保持不变 |

测试使用的工作簿、业务数据及含本机路径的测试脚本未上传。源码发布时将业务特定的明细表名替换为通用名称；部署者需匹配实际名称并执行验收。

## 部署验收清单

- 在备份副本上安装，确认模块和事件放在同一工作簿。
- 初次刷新无错误，区域与批次显示数量符合明细。
- 调整批次后仅目标 Planned 值变化。
- 超出区域容量时正确扩行，下面的区域引用仍正确。
- 同名项目分别修改，且排序后重新计算仍能正确定位。
- 手动新增明细后刷新可见。
- 无效批次和未配置区域明确报错。
- 保存、关闭、重新打开后功能仍可用。

## 已知限制

- 依赖特定布局，不自动识别任意工作簿。
- 按区域、批次和展示顺序定位，不具备持久业务 ID 或多用户冲突控制。
- 明细直接修改后需要运行刷新；没有明细变更自动监听或定时刷新。
- 只增加行，不自动缩减；新增区域和表头日期仍需维护。
- 程序重新生成项目展示区公式，不保留该区域的自定义展示公式。
- 刷新不具备完整事务回滚，发生错误后可能保留部分插行；原文件备份是必要保障。
- 不支持合并展示单元格、跨单元格数组、工作表保护状态下的刷新等情况。
- 无修改历史记录，也没有一键撤销宏操作。
- 大数据量性能、Mac、WPS、Excel 网页版均没有兼容性保证；网页版不运行 VBA。
- 未选择开源许可证；私有仓库不意味着授权第三方自由再分发。
