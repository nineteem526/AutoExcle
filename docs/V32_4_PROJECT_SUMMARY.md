# Excel 出货计划自动化｜V32.4 工作流总结

最后更新：2026-10-21
归档范围：截至 V32.4 的用户工作流、业务规则、主要修复、定向验证和已知限制。

> **版本与发布边界：**V32.4 是用户持有的专用 `.xlsm` 工作簿版本。本页是脱敏文档总结，不是工作簿或完整 VBA 源码的发布，也不表示仓库内的历史工作簿、源码或历史说明已同步到 V32.4。当前交付文件名为 `Shipping_Plan_Summary_V32_4_SystemLabels.xlsm`；它只是当时的本地交付，不是用户后续保存的业务数据权威版本。历史 Word 手册仅对应 V31.2，不能作为 V32.4 完整手册。

## 项目与数据边界

这是为 Windows 桌面 Excel 和固定工作表结构设计的 `.xlsm` 工作流，不是通用插件；不承诺在 Mac、WPS 或 Excel 网页版完整兼容。工作流分开处理来源读取、安装日期更新、计划批次、Summary、报表和异常检查。

来源由用户手动选择，工作簿以只读方式读取 `Task_Data`。仅采用 `Project_Step_Phase = "5 - Installation"` 且 Plant 不以 `Plant #XX` 前缀开头的记录；导入生成 Plant 清单和工作簿内部静态快照。它不是持续外部连接，不会追加来源中的新任务。现有工作簿仍有历史外链，因此不能宣称完全没有外链；“隐藏”也不代表加密或脱敏。

安装日期仅按 **Plant + Task Name** 完整联合匹配（忽略大小写和首尾空格）。唯一匹配且日期有效才更新；未匹配、多候选或日期无效时保留原日期并标记，不猜值。相同日期也算匹配成功，并清除本功能标记。此流程保护人工业务字段和固定的 P 列安排，不创建来源新任务。

## 当前工作表布局

### Detail Shipping planning

| 列 | 含义 |
|---|---|
| D | Product |
| E | Plant |
| F | Task Name |
| H | Ready |
| I | Installation |
| J | 类型 |
| O | Automatic |
| P | Planned |
| A / B | Shipment batch / Shipment No. of Logistics |

### Summary

计划号在第 3 行、Actual 在第 6 行，ATD / ATA / ATS 分别在第 7 / 8 / 9 行，Status 在第 10 行，任务从第 11 行开始。任务按 **Product → Plant → Task** 分层，容量动态扩展；批次移动限于相关局部范围，并执行映射校验。

### Program

表头在第 31 行、数据从第 32 行开始。计划参数起始日期使用 `L9`；旧隐藏单元格 `B11` 已停用。

补充批次编号（如 `1-1`）按文本保留，仅供人工选择，不参与 Automatic 推荐。删除补充船次仅通过现有安全删除流程，并须检查引用；不能把该流程用于基础船次。

## V32：计划批次与 Actual 分离

- Actual 默认复制原计划号，之后可由用户手动修改或清空；Actual 必须在跨计划组范围内唯一。改 Actual 不搬动任务、不改变 P，也不借用其他计划批次的日期。
- 不会因 Actual 为空而自动隐藏空批次，也不会动态重排批次或锁定状态下的编号。
- 明细 A 显示 Shipment Actual；Summary Actual 与明细 A 按 P 批次整组双向同步。
- Summary 中“有任务但 Actual 为空”及“没有任务但 Actual 非空”会标红。
- “恢复自动批次”只让符合条件的 P 恢复为当前 O，保留 Actual；“恢复默认船期编号”则把 Actual 恢复为原计划号。V32.1 将这一按钮名称改为“恢复默认船期编号”。

## V32.2：受限的公式保存与计算

V32.2 支持保存 `Formula2` 并计算受支持的普通 Excel 公式，包括 N+1、IF、计数、查找、内置安全函数、本地跨表引用，以及经验证的 `INDIRECT` / `OFFSET`。

这不是任意公式运行环境或安全沙箱。公式采用白名单和保守依赖限制（最多 20,000 个单元格、128 层）；不支持新增外链、UDF、名称公式、结构化引用、LET、LAMBDA、随机数或时钟类公式。若复杂公式结构变更后无法证明安全，程序拒绝处理。有效结果仍须是正整数、补充编号或空白，并保持唯一。

在 Detail 直接把公式编号改为值时会要求确认；取消会整体恢复。刷新、重开和保存需保留公式。V32.2 历史记录为 175 项回归检查和 10 项生命周期检查通过（共 185 项）；这是历史验证记录，不是性能保证。

## V32.3：原生删除的完整记录保护

修复前，整行清空与整行删除可能被误判为只编辑 A/B，导致清理后留下半条记录；结构移位还可能跳过失效标记。V32.3 保留 Excel 原生右键删除整行和 Delete 清空完整记录，没有新增删除按钮。

- A 列单独编辑仍会拦截；B 的编辑仍按同一计划组同步。
- 删除会使旧 Summary 映射和报表失效，需使用现有刷新或生成流程更新；不会自动重编号、不改 Actual 公式，也不改其他人工 P 值。
- 对真正无任务/无业务输入或只有原 K/AG 辅助公式的行，可按条件清理系统生成的 A/B 标签；不删除整行、不动辅助公式。
- 使用隐藏名称锚点识别结构移位。不支持任意删除/插入业务列，也不支持局部单元格上移/下移。
- 小计/总计整行仍受保护。若非法结构修改可以由 Excel Undo 撤回，应撤回；若不能安全撤回，程序明确报错并禁止保存，用户须关闭且不保存后重开。程序不会用旧行号把数据回填到已移位记录。

V32.3 的 115 项历史检查覆盖原生事件、手动/自动计算、连续/不连续筛选删除、AM 字段、保存重开、恢复自动、补充船次和日期报表等。检查项不是独立业务场景数。完整刷新报表使用隔离 fixture；原业务删除另与 Excel-only 基线比对。外链更新未验证，不能将其描述为可用。

## V32.4：系统行标签清理

V32.4 在 V32.3 基础上修复底部小计/总计行 A/B 中残留系统 Shipment 标签或编号的问题。首次启用宏打开时，按条件清除成对生成标签，保留右侧小计/总计公式及行结构。用户可只选这些系统行的 A/B 单格或多格按 Delete 清空；不能把系统行当作 Actual 输入入口。

右键删除小计/总计整行仍禁止；整列及局部单元格位移限制不变。39 项定向检查通过，覆盖手动/自动计算、清 A、清 B、清除块、同步后不重现、保存重开、C:AM 公式和 Summary Actual 链保持未改。COM 删除系统行时 Excel Undo 不可用，验证确认的是明确报错并禁止保存的路径；不表示所有失败都能自动撤回。

## 日常操作与删除建议

1. 批量操作前备份工作簿。
2. 删除任务时，选中目标行号并使用右键“删除整行”；要清空完整任务时，选取完整 A:AM 记录区域按 Delete。
3. 使用筛选时，只选择确实需要删除的可见行，避免选择跨越隐藏行的连续区域。
4. 对系统小计/总计行，仅清 A/B，不删除整行；禁止小计/总计整行删除。
5. 删除后刷新 Summary，并重新生成报表。若程序提示禁止保存，关闭且不保存后重开；不要通过另存绕过保护。

宏操作不保证可用 Ctrl+Z 撤销。不要关闭宏或降低 Office 安全策略来规避错误提示。按钮完成也不代表文件已保存。
